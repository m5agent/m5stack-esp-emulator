# Frontend lifecycle and local release recovery

Two concrete workflow faults are fixed. Every asynchronous shell load now owns
an independent detached child mount. Only the current generation may commit it;
a late constructor/dispose or rejection cannot alter a demoted 2D frame or a
new owner of the shared host. Valid committed-shell image failures detach the
UnitPanel and dispose that shell before showing the real saved framebuffer.
The mount uses 100% dimensions with zero grid min-size; the actual CoreS3
browser fixture verified 440x420 dimensions and automatic ResizeObserver
updates to 320x420, followed by owned-canvas disposal. Both PNGs were opened.

UnitPanel retains only this client's momentary bool/array release intentions.
An uncertain release may be confirmed or compensated only by a GET started
after uncertainty. A re-press cancels the earlier intent. Array compensation
preserves unrelated observed indices and active local holds. Queuing does not
spend the retry budget; the single automatic attempt is consumed only when a
compensation POST is actually attempted. Unavailable state, terminal state,
disposal and replaced intentions prevent that POST. Exhausted intentions stay
unconfirmed and require another user gesture; permanent failures do not loop.
Ordinary down/up adds no POST. Output replay and unowned fixture inputs do not
create release intentions or trigger input echo.

The final source passes 23 deterministic in-memory fault contracts. The bound
negative control uses preserved pre-fix sources. The existing Panel contract
(all 27 schemas/four viewports) and bridge contract (31 HTTP POSTs/12 trusted
pointers) also PASS. These browser stages and the focused mount stage preceded
only the final stale-rejection guard; their original exact fingerprints are
retained, with the earlier SessionVisual source snapshot. The final 23-case
report binds the final source including that guard. No older evidence, primary
27-Unit selection or host9 record was modified. No Device Service session was
started for these regressions; separate live fault evidence is coordinated by
root. No firmware/ROM binary is included.

Boundary: the server has no multi-client ownership arbitration. Two clients
using the same exact key/field cannot be distinguished by this local repair.
Arbitrary fixture fields, raw joystick polarity/scaling, mechanical bindings
and Fan attachments remain outside this change. No physical-hardware result
is claimed.
