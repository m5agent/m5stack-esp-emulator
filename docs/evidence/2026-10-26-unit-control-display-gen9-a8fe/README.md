# Display-control evidence from separate host batches

This archive selects actual Device Service control/browser executions separately
for AtomS3R, StickS3 and StopWatch. It is **not one continuous 15-case run**.
`batch-selection.json` records supplied batches and missing hosts. The reviewed
successful-batch gate requires five PASS reports, an actual root-observed exit-0
tool-result receipt and real post-execution history for every supplied host.
Incomplete or failed inputs remain internal. Each host retains its own original
summary, source freeze and exact 27-Unit canonical selection; the other Units
remain NOT RUN in that selection.

The new explicit `device-service-control-web-v1` contract binds unchanged real
controller assertions, product POST/readbacks, serial, direct PID/firmware/worker,
ZIP/frame and actual stopped history with literal `flash_retained=false`.
It does not relax the separate legacy dual-observer contract. Per-case receipts
preserve and explain preparation-time NOT RUN/BLOCKED fields.

Native readability refers only to each independently reviewed **actual final
captured frame**, with its exact hash and observed final lines. Neither intermediate
states nor every numeric extreme is visually validated by that classification.
The 23 authoritative font sources and runtime font/layout markers are separate
evidence layers; source arithmetic cannot grant visual PASS. Physical hardware
execution is NOT RUN. Other firmware hashes, hosts and controls inherit nothing.
The selected visual supplement pins its original native and execution reviews;
font/layout and captured serial fields are inherited exactly. Separate manually
observed native text and before-evidence browser framing retain their own scope.
Trusted command-line visual/completion SHA selections prevent mutated envelopes
from authorizing themselves by recalculating their internal hashes. Completion
is root's actual tool-result observation, not a new wrapper or kernel observation.

Each source reconstruction index binds all actual execution dependencies,
including the reviewed wrapper/manifest, all 105 preparation dependencies and
23 font evidence sources. There are 17 named probe Python files and an eighteenth
shared rtc_probe.py in the prepared VFS. Exact baseline commit/path/blob/SHA
references replace unchanged sensitive source bodies and reused image assets;
all other text sources are snapshotted. Baseline Git objects are needed for those
references. This archive excludes firmware, ROM, ELF and native libraries and is
not a self-contained runnable firmware distribution.

`host-validation-candidate.json` changes no runtime profile. Post-execution
review and archive tooling remain outside the runtime freeze. `archive-verification.json`
records source reconstruction, raw identity, PNG decoding, ZIP CRC and zero-exemption
content scanning. `SHA256SUMS` covers every public file except itself. External
agent-work-logs status remains NOT ARCHIVED until root supplies a verified archive.
All inputs are validated before private .work staging. The staged contracts are
verified before promotion, generated path envelopes are relocated, and final
paths are rechecked. A failed final check moves this newly created tree back to
private staging. Raw artifacts and source bodies are never rewritten.
