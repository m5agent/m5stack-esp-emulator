# Three-host sensor execution evidence

This archive preserves one explicit selection of three hosts and six sensors.
All eighteen original reports are required. A failed or missing case blocks the
whole archive; no successful subset is selected. Original reports, artifact
hash maps, preparation records, source-before maps, toolchain metadata, probe
sources, serial, browser records, ZIPs, PNGs and stopped history retain their
original bytes. Source bodies use .txt suffixes. Reused source images and any
sensitive unchanged baseline source body use exact baseline Git references.
Firmware, ROM, ELF, bytecode and native toolchain/runtime binaries are excluded.

The archiver verifies artifact identity and source-bound pure evidence gates.
Those checks do not classify native readability, browser framing, all numeric
extremes or physical RF/optical/electrical behavior. Preparation-time NOT RUN
fields are retained as preparation history. Actual execution authority remains
the unchanged same-session reports and artifacts. No runtime profile or product
metadata is modified. No external work-log archive is implied.

Controller, evidence-ZIP and retained-history frames are separate captures;
their individual hashes/dimensions never assert cross-request atomic equality.
Any separately SHA-pinned root visual review covers every distinct captured
final frame, retains its actual observed text, and remains a separate human
observation. Browser framing stays NOT REVIEWED.

Heart observations remain open: the unchanged official wrapper/native driver
can expose intermittent raw IR/Red zero samples, including transitions between
controller and later ZIP/history captures. The source-consistent FIFO/cache
explanation is not a proven runtime root cause: reference-BIN/native-source
mapping and time-correlated FIFO traces were not established. Two fresh matching
input observations do not promise a constant final value, BPM or SpO2.

The general QOM tree is bounded (/machine, depth 2, maximum 500 nodes) and can
truncate before the Unit chip. The evidence chain uses original chip-counter
queries, guest-qom Unit state, the retained contract path template and the
hash-bound UnitRegistry/DeviceService implementation. It does not provide an
independently retained raw narrow-QOM response for every derived chip path.
