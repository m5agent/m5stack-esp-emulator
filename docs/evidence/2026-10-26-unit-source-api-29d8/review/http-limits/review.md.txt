# UIFlow source API 文档与合同静态复核

日期：2026-10-26。范围：当前 worktree 的新增源码 helper、service/HTTP 接线、源码身份与证据合同及三份调用文档。未操作任何服务、API、guest、QEMU 或物理设备；未执行服务测试。具体文档冻结 SHA 与离线限额样例见同目录 `review.json`。

## 发现

未发现本轮必须阻断的新增代码缺陷。已修正文档中容易误读的一处合同：HTTP 原始 JSON body 与解码后的 caller source 各自受 1 MiB 限制；不能承诺任意 1 MiB 源码均可提交。

低优先级覆盖建议：`platform/tests/test_uiflow_source.py:129` 覆盖 helper 的数量、单文件及累计 UTF-8 字节限额，当前 source HTTP 测试尚无直接覆盖“源码仍在 helper 限额内，但完整 JSON 超过 HTTP 限额”的请求。可在既有 HTTP fixture 加一个源入口的超大 body 负例，断言 `413 body_too_large` 且不发布 artifact/firmware。这是公共请求边界的回归保护；本代理未修改测试或运行该 fixture。

## 双限额证据

- `platform/tools/serve.py:983` 的 `_read_json()` 仍调用 `_read_body(max_bytes=1024 * 1024)`；`:954` 对 Content-Length 超限返回 `413 body_too_large`，发生在 JSON 解析/固件 compose 之前。两条源码路由都使用该 JSON reader；未扩大旧 HTTP 限额。
- `platform/tools/uiflow_source.py:23` 定义 128 caller files、累计 1,048,576 UTF-8 bytes、单文件 262,144 UTF-8 bytes；`:94` 和 `:97` 分别执行单文件与合计检查。生成的 boot.py 单独计入 effective sources，而非 caller 总量。
- 仅用宿主 `json.dumps` 计算、没有发送请求：4 个文件各 262,144 个 ASCII 字符时，解码源码正好 1,048,576 bytes，而紧凑完整请求为 1,048,651 bytes；若每字符是 JSON 需转义的反斜杠，请求为 2,097,227 bytes。两个集合均在 helper caller 字节上限内，HTTP 层均应拒绝；这是静态预期，不是 live HTTP PASS。
- API、OpenAPI（普通 `/firmware`、便利 `/firmware/uiflow`、共享 files schema）与 Agent 指南现都明确双限额，提到字段名、路径、JSON 语法/空白/转义的额外开销及 `body_too_large`。

## 已知剩余边界

1. FirmwareStore 仍以完整 image SHA 命名 metadata，`:2680` 每次创建会覆盖该 image 的最新声明。同 image 的 generated/caller boot 声明，甚至不同 source kind，可能更新 metadata。source pin 能拒绝错配，避免静默错绑，但不能提供按 source 版本稳定查询 firmware metadata 的能力；客户端可能需重新 compose 再创建 session。已经创建的 session 使用冻结 provenance，不从后来 metadata 重建。指南已保留该 fail-closed/retry 边界。
2. reference 的 UIFlow2 家族/设备准入来自服务的 DeviceSpec 和本地 reference 配置；helper 明确不把“可 mount LittleFS”当成家族鉴定。`expected_base_sha256` 是 caller 可选固定，不能把此入口扩展为任意 base、加密或签名固件导入。
3. caller 源码正文确实存于内部 CAS；公开 metadata/session/ZIP 的 provenance 只有文件 hash/大小/路径和工具链。它不意味着 CAS 中不存在源码，也不意味着停止 session 会立即删除源码；保留/GC 走现有策略。
4. `test_uiflow_service.py` 的 offline contract fixture mock 了 DeviceSession.start，四主机 composition 用同一合成 base；它们不能证明四主机真实启动/Unit 数据面/Web 或物理硬件。指南单 Button 与多 Unit 程序均保持 PENDING，hardware NOT RUN。
5. helper 打包完成的 status 保持 COMPOSED_NOT_EXECUTED；实际 guest import、main 执行、ready marker、fresh serial、frame、Unit controller 计数和 evidence 仍需 root 通过真实可见 session 验证。原 Buzzer/IR、PWM 初始化观察缺口和共享 runtime 完整矩阵门禁没有被本入口关闭。
