# Shared browser Preview client contract (2026-10-27)

Only root edits sessions.js/sessions.html/serve.py/device_service.py. Each panel receives one shared optional `previewClient`; absent means legacy unchanged. Invalid non-null management_binding MUST remain managed and fail closed, never fallback to legacy mutation.

New module platform/web/preview-client.js exports `createPreviewClient({session,api})`. Instance public methods:
- `updateSession(session)`, `snapshot()`, `subscribe(listener)->unsubscribe` (call once immediately), `refresh()->Promise<snapshot>`, `dispose()`.
- snapshot: `{managed:true, synchronized:boolean, error:string, pending:boolean, preview:object|null, activeRun:object|null, desiredRun:object|null, transitionRun:object|null, frameContext:context|null, inputContext:context|null, canSubmit,canInput,canCancel,canRenew,canClose,cancelRunId:string|null}`. Deep-frozen detached result; polling never publishes a mutated object by reference.
- context: `{key,previewId,ownerEpoch,sessionId,runId,executionId,revisionId}`. key includes binding, preview generation, active Run identity/cancel/transition state. frameContext requires ready+bound, active running/completed, no cancellation/transition/other desired; input only active running. Unsynchronized/error/expired/closing/pending control mutation => no context. All IDs must be validated vs binding, response, generation and actual session. Unknown enums/identities fail closed.
- `captureInput()->context|null`; `matches(context,kind='input')->boolean` (`kind='frame'` allowed).
- `input(context,kind,command,options={})` kind exactly input/unit_input, options may contain keepalive. POST Preview/input with captured owner/run identity; check still current before dispatch and all response IDs + current identity after. Return the whole input receipt `{preview_id,run_id,execution_id,revision_id,captured_at,result}`. No auto replay of uncertain effects.
- `readSession(context,action)` action exactly units/device-state. Refresh server Preview before read and after read, check captured frameContext both times, GET captured session action, validate result session_id, return raw payload only if still same Run. Values/frame are separate samples, never atomic.
- `runRevision(revisionId,{idempotencyKey?,clientGeneration?}={})` returns original queued Run receipt after POST. Serialize local run admissions, refresh current CAS generation, use stable idem key for that operation, never automatically retry a conflict or ambiguous network failure; always reconcile afterward. Can accept rapid sequential requests, server latest-wins. Generate keys via crypto.getRandomValues/crypto.randomUUID, no Math.random. On transition mutation set pending/emit synchronously so old inputs/frames close promptly. Poll GET Preview and unique active/desired/transition Run IDs. Response receipts are not current state; don't overwrite newer state with an old receipt. Do not claim application READY.
- `runRevision` options additionally accept synchronous `beforeAdmission(snapshot)`. Invoke it after the final fresh CAS read and immediately before POST to guard the loaded complete-package baseline. A thrown error prevents admission; returning a Promise is invalid. The server CAS fences later concurrent changes. This guard does not authorize retry/rebase after conflict.
- `cancel(runId=snapshot.cancelRunId)`, `renew(ttl=600)`, `close()` capture binding+epoch and serialize where needed. Cancel is separate from slow run admission/package save. Each mutation reconciles state; no legacy endpoints.
- `refresh` must reject old binding/operation/request results, generation rewind and late old poll responses; timers at ~500ms during active/pending otherwise 1s (hidden 3s), no overlapping polling. api(path,options) is supplied; root will attach `.status/.code/.body/.effectPossible` to errors. No own authorization/token storage.
- `matches` is local fence; readSession also uses server bracket. Context changes must invalidate panel queues/held intents and old GET/POST bodies. Controls may release only captured Run; never retarget an old release to new Run. Server owns final held release during switching.

ProgramPanel additionally uses new root-owned GET `/api/v1/program-revisions/{revision_id}/files` -> `{revision:<same metadata>, files:{path:{encoding:'base64',data:<canonical base64>}}, limits:<existing limits>}`. Complete 1MiB/64-file immutable package, integrity checked host; browser must verify count/path/size/hash, using existing `Sha256` (works on HTTP LAN, no SubtleCrypto requirement). No new save format: POST /program-revisions `{source_kind:'uiflow2-package',entrypoint:'main.py',files:complete mapping}`, response metadata. Preserve untouched files including .mpy/resources; edit only main.py. Do not silently overwrite a dirty draft from polling/loading. Explicit load-current-package button; initial empty Preview may start a main.py-only workspace. External revision changes preserve draft, require explicit synchronize/load before overwriting another changed complete package. local rapid clicks snapshot complete package at click time; stale save completion must not override a newer click. Use shared runRevision; cancel independently; source remains editable during server preparing/starting/running. UI can show identities/status but START not app READY. Legacy ProgramPanel unchanged.

UnitPanel gets previewClient optional. Keep existing contract/attachments/visual mappings. Input uses captured context+previewClient.input(...,'unit_input',...). Extract result from receipt.result only after identity check. No legacy mutation fallback. Clear/invalidate request/input epochs, pending normal queue, local press/release intents and stale visuals when Run context changes; don't send old compensating release against new Run. Preserve necessary same-Run release paths; unknown effect => display unconfirmed, don't replay ordinary input. Poll via readSession(context,'units') for stable context; before no current Run load frozen definitions/attachments but don't apply unowned live values. Legacy behavior/test paths remain. Dispose unsubscribes but does not dispose shared client.

Root SessionVisual owns client lifecycle and subscription, routes host/touch input, renew/close, disabled reset; frames use Run URL and verify Preview/Run/execution/revision/PNG SHA before decode and commit (Sha256). Host identity change may rebuild shell; Run change only invalidates frame/input/state owner, retain shell and Unit assemblies. Terminal managed history may show explicitly labelled legacy last-session frame; never call it current Run frame. No unsupported reset endpoint added.
