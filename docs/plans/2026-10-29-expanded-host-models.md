# 新增主机真实模拟器接入

日期：2026-10-29。用户要求把模型仓库新增主机接入模拟器，重点覆盖 Atom、Stick 系列；
明确要求逐设备增加内部模拟系统，不能只增加模型。

## 目标与约束

模拟器已同步 `origin/main@0eb8f8fa（含本轮同步的 PR #22–29、#31–32）`，包含 PR #21 的启动渲染与 Core2 时钟修正。模型来源固定为公开
`yuyun2000/m5stack-models@4879ab51eb8bb11ce024e670ae6880529e3d0f42`；
本轮接入全部 21 个新增主机，主机视觉库存由 17 扩至 38，Unit 保持 184。
保留完整 Atom/Stick 家族、型号配置、贴图及公开组件交互。

沿用 Git 对象和显式路径/哈希白名单导入，不读取上游脏工作区，不复制私有研究、
原始 CAD/照片、依赖目录或原始证据。用户主 checkout、8787/8830 服务和无关
会话不作改动。新增视觉主机不自动获得 QEMU、Device Service 或 Unit 接线准入。

## 执行与验收

1. 核对公开远端固定 SHA、全部新增 controller 和配置，以及源码/贴图/许可差集。
2. 更新同步器白名单并重建 vendor、runtime-index、来源收据；维持单独的已审查 guide pin。
3. 通过现有公共工作台自动目录载入新主机；无运行后端的型号明确标注仅模型，
   不提示连接服务即可启动，不生成虚假固件/帧/外设数据。
4. 在独立静态端口逐主机和配置检查模型、贴图、前后视角、按键/显示/LED/关节
   公开接口、状态回读、无输入回声和清理；核验实际工作台搜索、选择与禁用运行入口。
5. 并行核对 AtomS3 系、经典 ESP32 Atom/Stick 系与独立芯片主机，逐板取得官方
   SoC、Flash/PSRAM、eFuse、GPIO、控制器和准确固件。复用现有 SoC/控制器实现，
   新增独立板胶水；不以相近型号 alias 掩盖接线差异。
6. 优先实现原版 AtomS3 与 StickC Plus2；在自有源码/构建目录编译，通过独立
   Device Service 实际启动官方固件，收集同 session 串口、frame、输入和外设回读。
   无屏型号必须具备真实 LED/button 数据面；StickV 等不同芯片单独记录执行后端依赖。
7. 将通过原生板级验证的型号纳入 WASM 源码构建和浏览器准入，逐设备检查准确
   固件启动、屏幕/LED、按键和相关外设；不继承其他板或旧 runtime 的 PASS。
8. 执行同步器、平台、Node 和生成器检查，导出公开子路径站点并核对生产资产。
   变更后的既有模型与浏览器固件显示路径按实际影响补回归。
9. 更新当前状态、Backlog、代码入口和 snapshot；归档有界结论与原始浏览器证据，
   检查公开范围后提交后续 PR。正式部署和物理硬件验证单独记录。

## 边界

视觉模型的 `modeled`、机械按压、LED/屏幕宿主接口和连接器位置，不等于真实
固件执行、总线/电气兼容或硬件验证。需要固件后端的后续工作按唯一 Backlog
跟踪，不能用同芯片或相似型号继承其它设备的运行结果。

编译、原生和浏览器闭环已通过。其余经典 ESP32 板型与固件缺口由 Backlog 维护。


后续真实运行已推进：AtomS3、AtomS3 Lite、StickC、StickC Plus SE 与 Plus2

Dial 旋钮实测丢步已定位到延迟 Python 回调读取相同当前引脚状态；50ms 操作点通过但不作为修复。
准确执行身份、后续回归与最终准入由[本轮证据](../evidence/2026-10-29-expanded-hosts/README.md)
和当前 Backlog 维护，不由本计划里的进度句授予通过。
