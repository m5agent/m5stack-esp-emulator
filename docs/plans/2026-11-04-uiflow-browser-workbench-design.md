# 浏览器启动、按键与 UIFlow 编程工作台

用户要求逐设备检查 GitHub Pages 启动速度和按键，默认加载 UIFlow，
并能直接在页面运行 MicroPython 代码。优先复现 Atom Matrix 与 StickC Plus，
其它设备保留各自的验证身份，不能继承 CoreS3 或 StackChan 的提速结论。

## 设计

继续使用单一 QEMU 实现。分别记录固件/ROM/WASM 下载、WASM 编译、
客体启动、应用 ready 与后续输入响应。性能配置必须绑定实际固件和板型，
保留 WDT、控制器和虚拟时钟语义，不用慢放或宿主伪造输出代替修复。

默认环境使用各板官方 UIFlow2 基底与公开的网页编程启动脚本；它不是
原厂联网菜单。保留现有固定示例作为可选入口。每份组合 Flash 必须重新
计算、核验哈希，逐板验证启动。仅视觉设备不能伪装成可运行设备。

在设备画面下提供有标签的 MicroPython 源码编辑区、运行、中断和输出。
通过 guest UART0 的真实双向 chardev 与 MicroPython raw-paste 协议执行，
支持 UTF-8、多行源码、异常和持续运行程序。传输有大小、队列与超时边界，
切板、停止和重启会取消旧会话的执行；不在宿主解释 Python。

按钮经模型/键盘输入、桥接、QMP 与板级 GPIO/触摸/PMIC 到达固件。
检查按下/松开、多来源重叠、失焦、取消和会话销毁；缺少真实板级路由的
按钮必须修复控制器后验证，不能只显示视觉按压。

## 验收

- 对所有浏览器准入设备逐板绑定新默认 Flash、运行时和 profile，验证
  UIFlow 启动、源码执行、真实输出、异常、中断、二次运行和 Worker 清场。
- 用固件自己的按钮 API 观察各个物理按钮的按下/松开；触摸、键盘和 PMIC
  保持其实际输入类型，不能用输入回声当结果。
- Atom Matrix、StickC Plus 先记录旧版本冷/暖启动，再比较候选版本；
  其它设备逐板给出测量与适用范围。
- 验证桌面与窄屏编辑器、键盘焦点、错误态和运行状态；执行影响范围的
  Node 合同、完整 Python 平台测试、目录/profile/覆盖/快照检查。
- 发布前保存有界可复现证据、精确源码与固件/运行时身份和清理观测；
  本地静态站与正式 HTTPS 结果分别记录，归档双远端工作记录。

当前状态：实施中，功能与性能尚未完成验收。
