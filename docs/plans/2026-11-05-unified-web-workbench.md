# 统一 Web 设备工作台

日期：2026-11-05。用户已确认 Pages 的 UIFlow 代码可运行，要求本机主界面与实时
会话界面的 Unit、代码和设备控制合并，不再在两个界面之间切换。

## 设计

以 `platform/web/index.html` 为同一个工作台，本机 `/` 直接提供它，Pages 继续
由 exporter 生成相同入口。保留旧 sessions URL 兼容，不重建或自动关闭旧会话。
设备画面、装配草稿、MicroPython 编辑器、输出和服务会话列表共处一页。

装配面板复用现有 Unit picker、真实主机接口与 runtime 合同。选择的 Unit
挂在当前主机模型上，不再创建第二个独立 Unit 模型。每设备保存独立草稿，
模型草稿不冒充已运行的控制器。启动时冻结拓扑；停止确认后才解锁接线。
实际运行状态和模型反馈继续来自同会话的 UnitPanel/QOM。

编辑器保留 browser UART raw-paste 路径；原生服务默认创建现有 Preview 管理的
UIFlow 会话，通过不可变 revision、Run、同 guest UART 执行与取消代码。
Unit、设备输入、画面和代码共享同一 Preview 的所有权与代际。
已有会话可直接打开；停止查看只释放本页视图。普通旧 UART 编程会话可运行与
替换代码，但其 API 没有独立中断，按钮如实禁用。只有本页创建的会话可随本页停止。

Pages 不获得本机服务的全部 Unit 执行能力。浏览器通路未实现的 Unit 需要
支持它的设备服务；只允许配置和模型装配，不伪造客体输入或外设输出。
本轮不改变 QEMU、板级 profile、固件准入、虚拟时钟或已记录启动问题。

## 验收

- Node 合同检查草稿冲突、异步模型所有权、会话代际、创建恢复、同 VM 编程、
  Run/帧身份与中断能力；无 guest 的浏览器检查统一入口与桌面/窄屏布局。
- 独立 Device Service 的新首页执行 CoreS3 + PIR，验证连续运行、导入、
  中断、实际 GPIO/QOM/串口/屏幕与停止前 ZIP、PID/lease 释放。
- 独立导出的 browser-WASM CoreS3 编辑器检查原编程路径和 Worker 正常清理。
- 运行完整平台套件、浏览器合同与受影响生成验证器；记录准确的执行范围，
  不继承其它设备的功能或物理属性。
